# Pulse product decisions

Owner decisions, in Adrian's words where it matters, with the date they were made and where they live in the code. Newest at the bottom of each section. Add to this file whenever a decision is made in a chat; it is the one place to check before changing behaviour.

## Shape of the product
- **Notch, hub, core.** Mac notch (Swift), Windows notch (Rust), one Tauri hub, one Rust core and CLI. No Dock or menu-bar item; the notch's right-click shows only Quit. (docs/plan.md)
- **The hub is the daemon.** "If the notch is on, the hub has to be on." The notch starts the hub hidden, checks every 5 s, restarts after 30 s if it died, and restarts it when its bridge heartbeat stalls for 90 s. Closing the hub window hides it; only quitting the notch quits the hub. (2026-10-09; HubLauncher.swift, windows/src/hub.rs)
- **The notch edge is right.** "I deliberately set it to right edge, since day 1." Never change it in code or by install. (2026-10-09)
- **The notch must never disappear.** Hidden launches unhide themselves; a blank Windows notch self-heals. (2026-10-09/10)
- **Pulse is exposed under the plain computer name**, no "(Pulse)" suffix. (2026-10-09)

## Gauges
- Six cells: Claude, Codex, CPU, Memory/System, Disks, Send, Tools. Every gauge can be turned on and off from the hub in one place; at least one stays on. (2026-10-10)
- **Ring pulse on Send:** the Send ring pulses for 6 s after an agent message is sent or received: green for delivered or queued, amber for held or sent, no pulse for refused or unknown. (2026-10-10)
- **Hover cards (design pass 2026-10-10, docs/card-design-pass):** one number per window ("79% left"), two lines per window, no truncation, titles without "Usage" except Claude and Codex, plan or scope as subtitle. Awaiting Adrian's pick of which to apply.
- **Claude ring numbers follow Claude Desktop's own cached usage** whenever it is under 30 min old; the CLI estimate and the token endpoint only when Desktop has nothing. (2026-10-10, ClaudeOAuthProvider)

## Send (nearby sharing)
- Keep the LocalSend protocol for files and clipboard between the owner's devices and the phone's LocalSend app. (2026-10-09)
- **Bottom bar: Copy last and Paste as equal buttons.** Paste is live only when the clipboard holds files, an image or text; the Copy last preview lives in its tooltip. (2026-10-10)
- **A paste lands on the other computer's clipboard**, not only in the save folder: text as text, one image as the image, otherwise the files; the card says "Copied from <computer>". Wire: `pulse.clipboard` in the LocalSend request. Drops of files are saved only. (2026-10-10)
- **Device trust: Allow / Ask / Deny (built 2026-10-10).** Hub Settings > General > Devices lists every device seen on the network or in a request (present first) with a rename, "nearby now" / "last seen", a refused count, a verified mark and an Allow · Ask · Deny control. Allow accepts with no card, files and text alike; Ask raises a card every time, text included (a message card shows only "<name> wants to send a message"; the text is delivered after Accept); Deny answers 403 at once, shows no card and counts `refused`. Denying cancels that device's waiting and in-flight requests; sending to a denied device is refused ("That device is blocked."). New devices start as Ask or Deny (the "New devices" setting, default **Ask** so first contact with the owner's own devices works; Deny-by-default is one click). Accepting a transfer never promotes a device to Allow. Records are `nearby_devices.json` in the sharing state dir (core/src/localsend/trust.rs, 200 entries, devices remembered in the old `known-devices.json` migrate to **Ask** (keeping a label if there was one; the old switch was off by default and a device was remembered after one accept, so it was never a grant). Migration runs only when the file is absent and no `.bad` set-aside exists; an unreadable file is set aside as `.bad` and replaced by an empty one, and any other read error leaves the file untouched until an explicit change. Allow, Deny and labelled records are never dropped; unlabelled undecided ones are capped at 200, oldest first. The old "accept from known devices" switch is gone.
  Identity, two proofs of the key behind a fingerprint, recorded as `proof` on the device and shown on its row: **certificate**: a Pulse sender presents its own LocalSend certificate as a TLS client certificate (the receiver requests but does not require one and checks the handshake signature) and the receiver hashes it; it must equal the fingerprint the request names. **callback**: a sender with no certificate (the phone, other LocalSend apps) and an Allow record gets one check: the receiver connects back to the address it called from, at the port it announced (else 53317), and requires the server there to hold the private key of a certificate with that fingerprint (the pinned handshake signature is verified for real, on every send too). Pass: Allow skips the card. Fail or no answer within 3 s: the card is raised, never an outright refusal. A callback is **relayable by anyone on the network while the real device is online** (a plain TCP forwarder passes it), so it is a convenience tier, not identity: that sender is still unproven for everything else (files in `Received (unverified)`, never the clipboard, the 200-file / 2 GB cap), shown on its row as "answered at its address (weaker: files only, kept apart, never the clipboard)", and `verified` is true only for certificate proof. A record that has ever proved a certificate never accepts a callback: a request for it without the matching certificate asks, and its proof is never changed by one. A certificate for a different fingerprint than the one named counts as unproven and asks. A request without proof never changes the alias/model recorded for a device that has proof (the claim is kept only as `alias_claimed`). Deny set while a callback or card is pending wins before any upload token is issued. Pulse sends only over TLS pinned to a 64-hex fingerprint: a device announcing http is listed but not sent to ("That device has encryption turned off in its app; turn it on to receive from Pulse."), an announcement never moves a device from https to http, and a malformed fingerprint refuses the send. Request sizes are summed with overflow checks and one file above 64 GiB is refused (400) before any card; the connection counter is released by a drop guard on every exit. Unverified: stricter signature checking may reject a LocalSend app whose certificate webpki cannot parse; not yet tried against the phone app. (2026-10-10)
- **Received files cannot harm the computer.** Every file written is created private (0600) and made 0644 when whole, never executable; it gets the system's "from outside" mark when closed (macOS `com.apple.quarantine`, Windows `Zone.Identifier` ZoneId=3; for a proven sender a failure is logged, for an unproven one the file is deleted and the transfer fails). Nothing received is opened automatically: the notch only reveals a file in Finder or opens a link on a click. A sender without certificate proof (callback proof included) saves into `Received (unverified)` inside the save folder whatever its trust state (the transfer's `savedTo` is that folder, which the notches already show), may send at most 200 files and 2 GB per request (refused 413 before any upload token), and can never put anything on the clipboard: `clipboard` is honoured only for an Allow sender with certificate proof; the Mac notch acts on a clipboard send only when the hub marked it so. (2026-10-10)
- After sending, the toast closes immediately. (2026-10-09)

## Tools
- **The phone side of Send lives in ScrapeRight's iPhone app; LocalSend on the phone is replaced. No separate Pulse phone app.** ScrapeRight already ships on TestFlight. No Send tab: when the app opens with something new on the clipboard, or a photo or file is picked with the plus button, it looks for Pulse computers and offers: Process (in ScrapeRight; what the phone cannot process, such as YouTube or Instagram, is queued through CloudKit for the Mac), and one "Send to <computer>" per Pulse computer found (none away from home, so only Process shows). No paste step and no share-sheet detour as the main path. A Receive tab beside Queue, Library and Settings holds what the computers send to the phone. The phone holds its own certificate, so it is a full Allow peer on the Mac and Dell (clipboard, normal save folder, no caps). No PIN. CodeRight stays for Claude chats. ScrapeRight's chat builds the app side (docs/scraperight-handoff.md). (2026-10-10)
- **The Send engine moves into RightKit, and Pulse moves onto it fully.** RightKit owns the `rightkit-send` crate and its iPhone packaging; Pulse's own copy (`core/src/localsend/`) was a stopgap while RightKit was busy and is deleted once the crate passes the parity suite: every security rule from the reviews as a named test, run against both engines, on Pulse's Rust version. Pulse keeps authority over the wire extensions and the trust rules. (2026-10-10)
- **On the phone, only received text is a scratchpad; pictures and files are saved.** Received text and links are removed as soon as they are used (copied, opened, sent to Process) or dismissed, and are not kept across app launches. Received pictures go to Photos. Received files are saved to ScrapeRight's own Received folder in the Files app; Settings can point them at another folder, for storage reasons. No history list, and nothing received is synced through CloudKit. Saving without asking applies only to a device that proved itself with its certificate. No text from a sender is shown before the offer is accepted; a trusted device is accepted without asking only when it proves itself with its certificate. (2026-10-10)
- **A sixth cell, Tools:** a grid of utilities on hover, no keyboard: Snip, Screen, Window (screenshots sent straight to the other computer's clipboard, nothing saved to the Desktop), Paste to other, Copy last, Lock screen. Screenshots do not live in Send. (2026-10-10)
- **Middle-click wheel:** the same tools as a radial dial under the pointer, anywhere. A middle click on a link passes through (the browser opens its tab); the link check is the accessibility element under the pointer, the rule HeardRight already uses. Adrian will disable HeardRight's middle click. Needs Accessibility. (2026-10-10)
- Three screenshot modes match macOS: region (⌘⇧4), whole display (⌘⇧5 first option), one window (⌘⇧5 second option). (2026-10-10)

## Chat (agent messaging, formerly "bridge")
- **Name: Chat.** Two sections in the product: Send and Chat. CLI becomes `pulse chat …` with `pulse bridge` kept as an alias for a while. (2026-10-10)
- Transport between computers is ssh with the owner's keys; the hub registers as a Claude peer; replies route by message id and device id. Receipt states mean one thing each: delivered, queued, sent, held, refused, unsupported, unknown. Incoming messages are unverified agent text, never the user. (docs/bridge.md, docs/bridge-astra-review.md, 2026-10-10)
- Codex threads come from the Codex state database (not archived, newest first) with folder and age. (2026-10-10)
- "Bridge off" is a core policy every path checks. (2026-10-10)

- **What Claude gets is in Claude's exact form.** Claude Code takes a message from another chat only when its wrapper has Claude's own attributes and nothing else, a sender class it knows that matches the chat's own (the owner's chats bypass permissions, so `bypass`), and a sender name of 64 characters at most; anything else is held for an approval and dropped while the sender sees "sent". "via Pulse" in the name marks forwarded text. Found after a security-review change lost every message for twelve hours. (2026-10-11)

## Phone
- **No Pulse phone app and no Telegram.** The phone side is CodeRight's Connected Computer mode, extended to attach to already-running Claude chats; Codex stays in its own app; sharing moves into ScrapeRight's iPhone app (see Send above); terminal work stays in Moshi. Pulse supplies the laptop connector pieces (chat discovery across accounts, transcript tailing, delivery into the original session). Handoff: docs/coderight-handoff.md. History: docs/phone-gateway-*.md. (2026-10-10)
- Laptops connect out to Hetzner; Hetzner never holds a key that opens a laptop. (2026-10-10)

## Permissions
- The hub's Permissions page states exactly which enabled feature needs which permission ("Needed for: …"), and "Not needed by anything you have on" otherwise. Entries: Accessibility, Screen Recording, Full Disk Access, Local Network, Background helper, Finder menu, Launch at login. (2026-10-10)

## Builds
- Dev builds from CI are signed but not notarized, and macOS will not register an app extension from such an app: the Finder menu (Cut, Copy Path, Open in Terminal) is absent on every dev install and returns with a notarized build. The Permissions row says so instead of "Off". (2026-10-10)
- **Dev builds stay sign-only, on purpose.** Notarizing and stapling take minutes per build and dev builds happen many times an hour; release builds are notarized. Do not turn on RightKit's `devArtifact.mac: "notarize"` for Pulse. Adrian: ask before requesting build-pipeline changes. (2026-10-10)

- **Pulse is fully on RightKit.** Every capability RightKit owns comes from its published package; Pulse keeps its own copy only until RightKit publishes an owner that does the same job, and a regression from a port is RightKit's to fix. The workspace is on Rust 1.98, which every RightKit crate needs. Ported: SQLite (rightkit-db), filename search (rightkit-search), the hub shell, platform check and release tooling at their published versions. Waiting on RightKit versions: local services, framing, directory listing and file watching, single instance, Swift keychain, overlay and file watching, Windows overlay and key sending, Mac signing and disk image. (2026-10-11)

## Claude accounts
- The restart button quits Claude politely for 20 s, force-quits for 10 s more, retries the sync while helpers wind down, and keeps a failure visible. The sync prefers the copy of a session that is further along (turns, then last message, then time), never the newest timestamp alone. (2026-10-10)
- The chat mirror is change-driven (FSEvents on the signed-in account's folder, plus the account change), with no timer. It copies one way, from the signed-in account to the others; the button stays as the restart and the full two-way merge. (2026-10-10)
- Pulse chat (the roster) lists in-app chats only; CLI sessions are reached over ssh (Adrian's words to the Dell chat). (2026-10-10)

## Working rules (how the chats operate)
- The Mac chat owns Mac, core, hub and docs; the Dell chat owns windows/src; one pushes at a time and tells the other first; CI runs must not cancel each other. (2026-10-10)
- No local Cargo or Swift builds for the public repo: CI builds. Dev builds are installed from the CI artifacts. (AGENTS.md)
- Never touch RightKit from the Pulse chat; report RightKit problems to the RightKit chats. (2026-10-09)
- Never capture Adrian's screen, raise windows or post notifications from an agent; QA uses the hidden crawl and CI evidence. (2026-10-09)
